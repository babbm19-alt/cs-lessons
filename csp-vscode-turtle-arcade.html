Getting VS Code ready for Python turtle

Everything you have written so far lived inside a web page that cleaned up after you. VS Code does not. It will run exactly what you typed, in the file you named, with the interpreter you picked — and it will tell you, in its own words, when one of those is wrong. Learning to read those words is the skill.

The one mistake that wastes the whole period. Do not name your file turtle.py. Python will import your file instead of the real turtle library and you will get AttributeError: module 'turtle' has no attribute 'Turtle', which looks like the library is broken when the problem is the name on your own file. Call it turtle_arcade.py. Also delete any turtle.pyc or __pycache__ folder if you already made this mistake.

What you are building

A game someone can actually play

Not a drawing. A game: it asks the player who they are, builds an arena around a target, and then waits — and every time the player clicks, it works out how close they got, scores it, and updates the screen.

That last part is the whole reason this task exists. A click comes in with an x and a y, you measure the distance to the centre, and you turn that distance into points. Change two words and that is hit detection. Change two more and it is collision. Every game you have played is doing some version of it.

You already know almost all of the pieces:

  • input() and int() — Activity 1.1.2
  • circle(radius, extent, steps) for the arena walls — the Arc Lab
  • fillcolor / begin_fill / end_fill for the rings
  • penup, pendown, goto to move without drawing
  • objects and methods — every single line is object.method(parameter)

Exactly one idea is new, and it arrives in Level 5. It is flagged when you get there.

Your colours and wall count will differ — they come from what the player types.

Level 1

Boot the cabinet

Make the window, name it, colour it, and put the title on the screen.

You must have

  • import turtle as the first real line
  • A screen object from turtle.Screen(), with .title() and .bgcolor() set
  • A turtle that writes the game name near the top using .write()
  • turtle.done() as the very last line of the whole program
# Turtle Arcade - your name here import turtle screen = turtle.Screen() screen.title("Turtle Arcade") screen.bgcolor("midnightblue") pen = turtle.Turtle() pen.hideturtle() pen.color("white") pen.penup() pen.goto(0, 250) pen.write("TURTLE ARCADE", align="center", font=("Arial", 28, "bold"))
Name every part. pen is the object you made. .write is a method. Everything in the parentheses is a parameter. That is the same sentence you labelled in the review game.
Level 2

Player card

Ask the player three things and put two of them on the screen.

You must have

  • A gamertag from input() — stays a string
  • A number of shots from int(input(...)) — must become a number
  • A number of arena walls, also converted with int() (use 3 to 8)
  • A second .write() showing the gamertag and the shot count
The trap you already met. "Shots: " + shots crashes with a TypeError, because shots is now a number and you cannot glue a number onto text. Wrap it: "Shots: " + str(shots).
You converted to a number with int() and now you convert back to text with str(). Both directions, same idea.
Level 3

Build the arena

One filled polygon, with the number of walls coming from what the player typed.

You must have

  • A new turtle for the arena, moved to (0, -200) with the pen up
  • A fillcolor, then begin_fill()
  • arena.circle(200, 360, sides) — all the way around, cut into sides straight walls
  • end_fill()
Why start at (0, −200)? The centre of a turtle circle sits one radius to the turtle's left. Facing east at (0, -200), left is straight up — so the centre lands on (0, 0) and your arena wraps the target instead of sitting beside it. That is the same rule the Arc Lab was built on.
Level 4

Draw the target

Three filled circles, largest first, all centred on (0, 0).

You must have

  • For each ring: pen up, goto(0, -radius), pen down, set the fill colour, begin_fill(), circle(radius), end_fill(), pen up again
  • Radii 120, then 80, then 40 — in that order
# Outer ring - 1 point target.goto(0, -120) target.pendown() target.fillcolor("white") target.begin_fill() target.circle(120) target.end_fill() target.penup() # now do the same thing for 80 (red) and 40 (gold)
Yes, you are writing nearly the same eight lines three times. Notice how annoying that is — it is the exact itch that functions were invented to scratch, and you are about to write your first one.
Level 5

Make it playable — the one new idea

Up to now every line ran once, top to bottom, and then the program was done. Now you write a block of code that does not run yet — it sits there, and the screen runs it every single time the player clicks.

A function is a named block of instructions that waits until something calls it. def shoot(x, y): creates one called shoot. The x and y are parameters — the same word you labelled in circle(50) — and the screen fills them in with wherever the player clicked. screen.onscreenclick(shoot) hands your function to the screen. Notice there are no parentheses after shoot there: you are handing over the function itself, not running it.

You must have

  • A marker turtle and a hud turtle
  • score = 0 and shots_left = shots before the function
  • def shoot(x, y): containing:
    • global score, shots_left — so it changes the real ones, not copies
    • marker.goto(x, y) and a marker.dot(10, "black")
    • distance = marker.distance(0, 0)
    • an if / elif / else chain turning that distance into points
    • updates to score and shots_left, then hud.clear() and a fresh hud.write(...)
  • screen.onscreenclick(shoot) just before turtle.done()
def shoot(x, y): global score, shots_left marker.goto(x, y) marker.dot(10, "black") distance = marker.distance(0, 0) if distance <= 40: points = 10 elif distance <= 80: points = 5 # ... you finish the rest
Indentation is not decoration in Python. Every line that belongs inside shoot is indented four spaces. The moment a line goes back to the left margin, Python decides the function is over.
Boss Level

Make it end properly

Right now the player can click forever. A game has to know when it is over.

Requirements

  1. The number of shots comes from the player (Level 2) and counts down with each click.
  2. When shots_left reaches 0, the HUD stops showing the score line and shows a final message that includes the player's gamertag and their score.
  3. Extra clicks after that do nothing at all. No negative shot counts, no extra points.
How to stop the extra clicks. The first thing inside shoot checks whether the game is already over, and leaves immediately if it is:
if shots_left <= 0: return
return means "stop running this function right now." Every game has a version of this guard. Without it, a player can keep firing after they are dead.

🏆 If you finish early

  • Make a miss cost a shot but also flash the HUD a different colour.
  • Let the player choose the bullseye radius, and scale the other two rings from it.
  • Move the target to a new random spot after every hit. (Look up import random and random.randint.)
  • Add a second player and alternate turns.
Video Game Design team: the guard clause, the distance check, and the score update are three of the four things in every game loop you will build this year. The fourth is drawing a frame, and you have been doing that since Activity 1.1.1.
